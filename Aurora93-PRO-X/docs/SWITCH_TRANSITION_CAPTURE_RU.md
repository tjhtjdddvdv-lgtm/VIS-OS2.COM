# Stage 114 — запись переходов Laptop/Tablet

Новый монитор периодически вызывает существующий read-only probe `EVIOCGSW` и
выводит полный отчёт только при первом чтении или изменении состояния. Он не
читает поток `input_event`, не забирает события у рабочего стола, не записывает
sysfs и не переключает режим интерфейса.

## Запуск на DIGMA Citi 1804

Из корня репозитория в Linux Live:

```bash
sudo python3 Aurora93-PRO-X/scripts/monitor_convertible_switch.py \
  --interval 0.5 --duration 180 \
  | tee VIS_OS_CITI1804_SWITCH_TRACE.txt
```

Сначала оставьте DIGMA в положении ноутбука примерно 10 секунд, затем медленно
переведите экран в положение планшета и обратно. Во время записи не нажимайте
клавиши, которые могут менять состояние крышки/питания. Если переключатель не
объявлен или чтение запрещено, отчёт сохранит `unknown`/`incomplete`; это не
означает, что аппаратного датчика точно нет.

При необходимости измените длительность и частоту, например `--interval 1`
для более редкого опроса. После завершения отправьте `VIS_OS_CITI1804_SWITCH_TRACE.txt`
и обычный отчёт:

```bash
sudo python3 Aurora93-PRO-X/scripts/probe_convertible_switch_state.py \
  > VIS_OS_CITI1804_SWITCH_STATE.txt
```

## Интерпретация и ограничения

- `SW_TABLET_MODE=laptop(0)` / `tablet(1)` — текущее значение input switch,
  сообщаемое ядром; переход должен совпасть с физическим движением корпуса.
- `SW_LID` — состояние крышки, которое само по себе не эквивалентно hinge/tablet mode.
- `unknown`, `incomplete` или `conflict` не разрешают автоматическое переключение.
- Если значение не меняется, это ещё не доказывает отсутствие датчика: он может
  быть представлен через ACPI/platform sysfs, другой драйвер или вообще не
  поддерживаться текущим ядром.

Stage 114 — только сбор диагностической трассы. Он не включает автоматический
переход режимов, не меняет Stage 101/102 UI и не подтверждает работу DIGMA.
